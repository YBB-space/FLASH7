# ALTIS FLASH7

ALTIS 지상 관제 애플리케이션입니다. 공통 통신·텔레메트리·미션 로직을 공유하며 PC와 모바일 화면 소스를 분리합니다.

## 빌드와 실행

```bash
npm run build
npm run check
python3 -m http.server 4178 --bind 127.0.0.1
```

`http://127.0.0.1:4178/` 또는 `flash7.html`을 엽니다. 빌드와 기본 검사는 Node 내장 모듈만 사용합니다. `?runtime_modules=1`은 소스 모듈 진단 모드입니다.

## GitHub Pages 배포

공개 주소는 `https://flash7.kro.kr/`입니다. `main`에 푸시하면 GitHub Actions가 빌드·검사를 실행한 뒤 웹 자산만 `_site/`에 모아 배포합니다. 로컬 패키징은 `npm run package:pages`로 실행하며, `_site/`는 Git에 포함하지 않습니다.

사용자 도메인의 CNAME 대상은 `ybb-space.github.io`이며, 저장소의 Pages 설정에도 `flash7.kro.kr`을 등록합니다. HTML·런타임·스타일 생성물은 계속 소스에서 빌드합니다.

## 소스 구조

| 영역 | 소스 |
| --- | --- |
| 공통 문서와 부팅 | `ui/shared/document.html` |
| PC 마크업·스타일 | `ui/desktop/` |
| 모바일 마크업·스타일 | `ui/mobile/` |
| PC·모바일 레이아웃 동작 | `scripts/ui/desktop/`, `scripts/ui/mobile/` |
| 화면 판별과 이벤트 수명 | `scripts/ui/shared/` |
| 공통 통신·데이터·미션 | `scripts/flash7-*.js` |
| 공통 스타일 계층 | `styles/src/` |
| 런타임 순서와 앱 수명·상태 저장소 | `flash7-loader.js` |

생성물 `flash7.html`, `flash7.runtime.js`, `styles/flash7-app.css`, `firmware/manifest.json`, `mobile_app_native/www/`는 직접 수정하지 않습니다. HTML·CSS 조각은 원래 위치에 조립되어 DOM 순서와 스타일 우선순위를 유지합니다.

## 시작 화면과 연결

지상국만 연결되면 **기기 찾는중 / FC 연결하기**를 표시합니다. FC 연결 가이드에서 번호 순서대로 연결 방법을 확인할 수 있으며, **지상국 화면 진입**으로 FC 연결 전에도 진입할 수 있습니다. FC의 유효한 텔레메트리가 감지되면 자동으로 진입합니다. USB 연결과 FC 수신 상태는 현재 연결 세션을 기준으로 구분합니다.

## 3D 화면

- PC의 3D 화면에서는 오른쪽 하단에 작은 가로형 비행 지도를, 왼쪽 하단에 시퀀스 시간과 고도·속도 수치를 표시합니다. QUICK DATA는 보조 텔레메트리 화면에 배치하며, 고도·속도·상태·SD CARD·점화 지연·ARM·PYRO·GYRO XYZ 자세각·가속도와 연결·칩 온도·성능·배터리를 표시합니다. 데이터가 없으면 `--`로 표시합니다.
- 보조 화면의 STAGE 1 링크 품질은 RSSI(dBm)·LOSS(%)·RX RATE(Hz)와 최근 30초 추이를 표시합니다. 수치 버튼으로 그래프를 전환하며, 기존 대시보드와 같은 RSSI 유효 시간·중계 경로 판단을 사용합니다. 처음 연결할 때 이력을 받고 이후에는 변경된 수치만 전달합니다.
- 보조 화면은 뷰포트 높이에 맞춰 스크롤 없이 표시합니다. 가로형 PC에서는 미션 타임라인을 상단에, QUICK DATA를 왼쪽에, 비행 차트·링크 품질·에어브레이크 패널을 오른쪽 2×2로 배치합니다. 3D 화면 지도는 가로형 비율을 유지합니다.
- 기본 미션 **ARAEA-I**는 1단 로켓의 에어브레이크 미션입니다. 시뮬레이션에서는 단분리 없이 10,000 ft(3,048 m)를 목표로 에어브레이크 전개율과 공통 서보 각도를 자동 제어합니다. 보조 화면의 타임라인·전개율·서보 그림에 함께 반영하며, 실제 에어브레이크 제어 프로토콜은 아직 구현하지 않았습니다.
- 보조 화면의 **ALTITUDE / SPEED**에는 고도(m)와 속도(m/s)를, **TELEMETRY**에는 가속도(g)와 GYRO X·Y·Z(°/s)를 표시합니다. 자이로 세 축은 0을 중심으로 같은 눈금을 사용하며, 선택된 스테이지의 기록만 표시합니다.
- 보조 화면의 차트 범위에서 **DETAIL**은 TELEMETRY의 작은 변화를 확대해 보여 주며, 눈금 밖 피크는 경계 화살표와 실제 **PEAK** 값으로 표시합니다. **FULL**은 모든 피크를 포함합니다. 차트에 마우스를 올리면 단위별 표시 범위를 확인할 수 있습니다. 표시 범위를 바꿔도 기록·내보내기 데이터는 바뀌지 않습니다.
- 같은 PC·같은 브라우저에서 `split-display.html`을 열어두면 메인 화면을 자동으로 찾습니다. 메인·보조 화면 새로고침, 연결 재시작, 페이지 복귀 후에도 자동 재연결하며, 기존 연결은 우선 유지합니다. 미연결 상태에서 같은 프로젝트의 메인이 하나뿐이면 그 화면에 자동으로 연결합니다. 메인이 여러 개면 임의로 선택하지 않습니다. 처음 창을 열 때는 **화면 스플릿 → 보조 화면 열기** 또는 연결 링크를 사용할 수 있으며 **한 화면으로 계속**도 지원합니다.
- 보조 화면은 메인의 텔레메트리를 받아 표시하며 보드에 접속하거나 명령·기록을 실행하지 않습니다. 메인 창은 계속 열어 두세요. 다른 PC·휴대폰은 아래 온라인 미션 기능을 사용합니다. 직접 파일을 연 경우에는 메인의 **보조 화면 열기**를 사용하세요.
- 제어 센터의 **3D 화면**에서 입체·상단·측면 시점, 기체 추적·시점 고정·전체 경로 맞춤과 줌을 조절합니다. 전체 경로는 두 스테이지를 함께 포함합니다.
- 마우스 드래그는 회전, 우클릭·Shift 드래그는 이동, 휠은 줌입니다. 이동하면 시점이 고정되고, 직접 조절한 줌은 자동으로 되돌아가지 않습니다.
- 회전·이동으로 카메라가 바닥 아래로 들어가지 않도록 제한합니다. 일반 줌아웃 범위를 줄였으며, 전체 경로 보기에서는 궤적을 담는 데 필요한 거리와 약간의 여유만 허용합니다. 줌 한계에서는 해당 버튼이 비활성화됩니다.
- 모바일 미리보기에서 확대 버튼을 누르면 크게 볼 수 있습니다. 확대·가로 화면에서는 한 손가락으로 회전하고, 두 손가락으로 확대·축소 및 이동합니다.
- 격자 버튼은 기준선을 숨기며, 초기화 버튼은 기체 추적과 기본 시점으로 돌아갑니다. 확대 화면에서 `0`은 초기화, `Esc`는 닫기입니다.
- 실제 궤적의 단위·비율과 기체 자세 계산은 유지합니다. 3D 배경은 상대 좌표를 사용하며, 절대 방위를 가정한 지형은 켜지 않습니다.
- 하늘과 중성 회색 바닥을 구분합니다. 격자의 실제 간격과 안개 거리는 줌과 무관하게 유지하고, 화면에서 너무 작아진 선만 흐리게 표시합니다. 하늘은 카메라 방향을 따르며, 입체 시점의 줌은 카메라 높이와 거리를 함께 조절합니다. 3D 시야각은 56도입니다.
- 고해상도 캔버스는 모바일 150만·PC 300만 픽셀을 목표로 조절하며 CSS 해상도보다 낮추지 않습니다. 조작 중 갱신은 프레임 단위로 합칩니다.

## 온라인 미션 · 추적과 회수

시작 화면의 **온라인 모드** 토글에서 접근 코드를 입력해 별도 기기의 미션을 조회합니다. PC에서는 **제어 센터 → 온라인 미션 공유**에서 중계 주소와 송신 키를 입력하고 공유를 시작합니다. 코드는 기본 2시간 유효하며 코드 소지자는 선택한 스테이지의 텔레메트리·차트·에어브레이크·링크 품질을 조회할 수 있습니다. 조회 화면에는 보드 연결·명령 전송 경로가 없습니다. 기존 같은 브라우저 보조 화면과 독립된 기능입니다.

**시뮬레이션에서도 같은 온라인 공유 경로를 사용합니다.** 실제 데이터와 구분하는 배너를 표시합니다. 서버 없이 확인하려면 온라인 모드의 **하강 시뮬 미리보기** 또는 `mission.html#demo=descent`를 엽니다. 이 미리보기는 로컬 목업이며 온라인으로 송신하지 않습니다.

PC의 **제어 센터 → 추적·회수 예측**, 조회 화면의 **추적·회수** 탭에서 GPS 위치, 하강 기반 착지 시간·영역, 낙하산 전개 근거를 확인합니다. 관측 위치와 발사점 대비 높이를 입력하거나 휴대폰 센서 연결 버튼을 누르면 방위각·고각과 조준 방향을 표시합니다. 휴대폰 위치·방향은 해당 기기에만 남습니다. 센서 사용에는 HTTPS와 사용자 권한이 필요하며 실제 휴대폰별 정확도는 현장 검증이 필요합니다.

착지 계산은 하강 중의 기압 고도 변화와 GPS 수평 이동을 사용합니다. 지면 높이는 발사점과 같다고 가정하며 수동 변경할 수 있습니다. 지형·바람 수치예보를 사용하지 않고, 표시 반경은 보정된 통계적 신뢰구간이 아닙니다. 전개 명령과 하강 추정은 실제 낙하산 확인 센서와 구분합니다. GPS 이상값, 오래된 데이터와 스테이지·미션 변경을 처리하고 수신 중단 후 예측 갱신을 중지합니다.

중계 서버 소스와 설정은 [`services/mission-relay`](services/mission-relay/README.md)에 있습니다. Cloudflare 계정 연결·실제 중계 배포는 별도 단계이며 GitHub Pages만으로 기기 간 실시간 중계를 실행하지 않습니다. `npm run check`는 추정·스키마·온라인 토글 회귀를 포함합니다. 로컬 Worker에서 조회자 10개 동시 수신·재연결·권한 검사는 `services/mission-relay`의 `npm run test:integration`으로 실행합니다.

## 정리한 기능과 코드

- 테트리스·이스터에그·보상 창과 로고 연속 클릭 이벤트
- 더 이상 진입점이 없는 별도 홈·카운트다운 화면
- 마크업이 없는 링크 토폴로지 창과 이전 알림 표시 경로
- 표시되지 않는 모바일 보조 중단 패널
- 숨겨진 PC 메뉴와 클릭 전달 프록시: 제어 센터가 현재 동작을 직접 호출합니다.
- 호출되지 않는 이전 궤적 계산·시리얼 탐색 함수, 빈 UI 갱신 함수, 사용하지 않는 상태·지역 변수
- 마크업이 없는 DOM 바인딩과 연결된 이벤트·스타일, 중복 viewport 갱신 리스너
- 이전 진입점·빌드 별칭과 구버전 런타임 별칭

코드 정리 작업 시점 기준 JS 소스는 2,156,548 → 2,046,166바이트, CSS 출력은 1,204,329 → 1,141,969바이트로 줄었습니다. 구형 네이티브 빌드 산출물과 중복 복사본도 제거했습니다.

현재 시퀀스·안전 제어·보드 연결·저장·리플레이·미션·하드웨어·OTA 기능은 유지합니다. 보드 프로토콜의 프레임 구조와 저장 데이터 형식은 바꾸지 않습니다. 앱 저장소와 전역 객체는 FLASH7 이름을 사용합니다.

## 검사

`npm run check`는 프로젝트 이름 일관성, DOM 바인딩 대상, 생성물 최신성, 런타임 순서·구문, 펌웨어 체크섬, 플랫폼 레이아웃·수명·시작 타이밍과 3D 맞춤·줌 제한·렌더 예산 회귀를 확인합니다.

`node benchmarks/*regression.mjs`처럼 여러 파일을 한 번에 Node 인수로 전달하지 말고, 각 파일을 개별 실행합니다. 프로토콜 회귀는 64바이트 이전 헤더 호환성과 현재 80바이트 미션 동기화 메타데이터를 함께 검사합니다. 리플레이는 데이터 선택 후 진행 버튼에서 화면을 전환하는 현재 흐름을 검증합니다. `npm run check`에는 보조 화면 재연결·타임라인·링크 품질, 제어 센터, ARAEA-I 비행, 카운트다운 음성, USB 연결과 시작 화면 FC 연결 흐름의 회귀 검사가 포함됩니다.

HTTP에서 PC·모바일 세로·모바일 가로의 번들/소스 부팅, 시뮬레이션 텔레메트리, 제어 센터 이동을 검증합니다. `file://` 시뮬레이션의 Leaflet `_fadeAnimated` 오류는 별도 해결 대상입니다. 실제 보드 연결과 iOS/Android 바이너리 빌드는 이번 코드 정리의 검증 범위에 포함하지 않습니다.

## 네이티브 웹 자산

```bash
cd mobile_app_native
npm run sync:web
npx cap copy
```

`sync:web`은 앱과 보드 이미지 메타데이터를 빌드·검사한 뒤 실행 자산만 복사합니다. `cap copy`는 iOS/Android의 웹 복사본과 앱 설정을 갱신합니다. 보드 이미지 자체는 관제 앱 버전과 독립적이며 원본 체크섬을 유지합니다.

일부 지도·3D·대화상자는 아직 DOM을 공유합니다. PC·모바일의 나머지 화면은 이 소스 경계를 기준으로 계속 분리할 수 있습니다.
